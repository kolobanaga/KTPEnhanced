KTPEnhanced
Client-side equivalent of the kimi-k3-jb server patch: injects a reasoning_content prefill for Kimi/Moonshot/GLM models, preserves prior reasoning across turns, and trims to context budget.
Appended as a partial assistant message; the model continues thinking from this text.
Applies only when the current model id contains one of these.
The "partial" flag is a field of the Kimi API only. It is sent when the model id contains one of these. Officially supported by the Moonshot provider alone; on any other endpoint expect a 400, a silently ignored flag, or behaviour nobody documented. On the official Moonshot AI Chat Completion Source the core sets this flag itself when the request ends with an assistant turn. Empty filter = the mode is off.
Required: with thinking disabled the model treats the prefill as reply text instead of reasoning.
Re-attaches stored extra.reasoning to previous assistant messages. Only turns that actually have stored reasoning are affected — a non-reasoning model or a source that was not asked for reasoning simply has none to send.
In a group chat several characters take turns, and only the one being generated is "you". All characters sends everyone's stored reasoning; Only the current character keeps the others out so the model is not told it thought things it never thought; None sends no prior reasoning at all. No effect outside group chats.
Last K sends reasoning for the newest K turns only; Last K + Omitted also keeps older turns, but replaces their reasoning with the placeholder below. Both spend far fewer input tokens and leave more room for actual chat history than All. 0 is allowed: no real reasoning is sent at all — Last K then forwards nothing, and Last K + Omitted puts the placeholder on every turn.
Sent as reasoning_content instead of the real reasoning of older turns, so the model still sees that thinking happened there. Left empty — nothing is sent for those turns.
The core trims the history BEFORE reasoning is attached; this re-checks the budget after and drops the oldest user/assistant turns to fit "Context Size" minus "Response (tokens)".
DeepSeek drops the reasoning_content of earlier turns unless the request carries tool definitions, so this adds one never-callable noop_placeholder function to flip that. DeepSeek's own endpoint documents that a request with tools must replay every prior reasoning_content verbatim or it answers 400, so keep this on All above there; other providers do not enforce it. If the model calls the placeholder anyway, the resulting tool messages turn this extension off for that chat.
